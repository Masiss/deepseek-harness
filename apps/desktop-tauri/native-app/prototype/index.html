A low-risk approach is to keep the current configuration shape and make fallback behavior explicit:

  • Parse the user file when it exists.
  • Use documented defaults for absent optional fields.
  • Return a clear error for malformed values instead of silently replacing them.

That keeps startup predictable while making configuration problems easier to diagnose.

Settings loader review

The settings loader should keep defaults explicit and report malformed values instead of silently replacing them.

Current behavior

Optional values inherit the documented default. Invalid values stop startup with a message that names the setting and the expected value.

Suggested follow-up

Keep the current configuration keys, add a focused test for missing optional fields, and verify that a malformed value still returns an actionable error.
