# Parity checklist — native desktop vs web client

A screen is done only when it runs on the native app and its probe passes.
Legend: ✓ transport/API available · ◐ native UI partial · ☐ not started

## Native UI implementation update — 2026-11-06

The native gpui shell carries the expanded prototype views and bottom utility dock. Plugins, Skills, Marketplace, Document preview, Goals, Settings, Explorer and Sessions remain in the native rail; Terminal, Jobs, Schedules and Deliverables open from icon buttons in the lower-right dock. The dock switches one panel at a time, supports close buttons, and retains Host-backed panel actions.

The shell runs on **`gpui` 0.2.2** (GPU-first) with **one binary**, `dsh-desktop-native-app`, and a `shell/` presentation layer on top of the shared framework-agnostic modules. The egui shell, its `egui_kittest` AccessKit harness, and its PNG baselines were deleted on 2026-11-06. In their place `src/harness.rs` opens the real `DesktopApp` in gpui's test window and reads the layout the renderer produced: `cargo test harness` checks bar heights, dock widths, dock thresholds, the Changes toggle, page-versus-conversation surfaces, and the command palette, and compares rectangle reports against `tests/snapshots/shell-<width>x<height>.txt`. `native-journey-probe.sh shell` runs the same harness against the packaged Host: the shell connects, creates a Session through its own RPC path, prompts a mock model, approves its escalated `bash` call, and reads the tool result and assistant turn back. gpui 0.2.2 ships no accessibility tree at all, so AccessKit-style assertions are unavailable in this renderer and the harness asserts rendered geometry plus shell state instead; there is still no pixel output. Every AccessKit, kittest, PNG-snapshot, or "native panel" claim below is historical evidence from the deleted harness, not a currently runnable gate.

Current native suite: **185 pass, 1 ignored** (8 drive the headless harness; the ignored one is the packaged prompt-to-approval journey). Runnable packaged probes are `native-journey-probe.sh terminal|timed-question|model-default|shell`, `appimage-probe.sh`, and `size-gate.sh linux-x64`. The former `panels` and `update-ui` GUI journeys went with the harness, so Marketplace install, Office preview, and update-modality evidence now comes from the Host-side probes that remain. Physical review of the native views stays with the owner.

## Core
- ◐ Session list (`session/list`) — separate `session_list.rs` renderer for projected titles, running/blank markers, relative update age, identity on hover, bounded labels, and arrow-key navigation when no text editor owns keyboard input; the packaged panel journey refreshes and reads back the probe Session after attempting search
- ◐ Session viewer / log (`session/page`) — async page with older-page navigation using Host `beforeSeq` and bounded turn windows; every loaded page merges into the same ordered transcript as live events (deduplicated by `seq`), older pages insert ahead of newer rows, and a page window no longer replaces retained history. The raw seq/type event list was removed, so history and live events have one renderer. Packaged journey reads the current page before and after Host restart; pagination is covered by the gpui kittest against the fixture Host
- ✓ Tool-call status derivation — M2
- ✓ Chat submit (`session/prompt`) + follow (`session/follow`) — composer with **file attachment** and **Cancel turn**; history and live events render through the transcript projection; a mock-model run proves prompt → approval → tool → question on the packaged runtime. The composer holds a stable `id_salt`, because an auto id moved with the transcript above it and silently discarded every keystroke; `Ctrl+N` creates a Session and focuses the composer
- ✓ Chat cancel (`session/cancel`) — composer exposes Cancel turn while the assistant is working
- ✓ Follow stream (`session/follow`) — shared authenticated mux with reconnect; snapshot records and live events feed one transcript
- ◐ Transcript projection — durable user/assistant messages, provider reasoning, tool calls and results, approvals, jobs, todo lists, deliverables, goals, plan mode, feedback, and the streaming assistant draft; `Transcript::merge` accepts history pages, windowed follow snapshots, and live events in any arrival order, sorts by `seq`, projects each event once, and keeps the newest rows under the row/byte budget. `transcript_view.rs` headless tests include a 1,000-row transcript constrained to the viewport scroll region; the gpui kittest covers opening an old Session, a snapshot arriving during a page load, switching Sessions, tool events, a 2,100-event history, and pagination through the "Load older events" button
- ✓ Permission approval — `$events` mux + allow-once/reject/delegate; `scripts/approval-probe.sh [allow|reject|delegate]` drives a mock model's escalated bash call through every decision on the packaged runtime: allow runs the command (marker outside the workspace), reject and delegate log the audit outcome and never run it
- ◐ Model selection (`session/modelCatalog`, `session/selectModel`) — composer picker groups providers/models, shows the catalog default, selects the model's default effort, and offers its reasoning efforts. `native-journey-probe.sh model-default` uses a fake account grant and loopback-only `/models` server, then verifies profile-default initialization and catalog read-back through the packaged Host and native picker
- ◐ Session management (`search`, `create`, `rename`, `fork`) — `packaged-journey-probe.sh` completes a turn against a local mock model, forks the Session, and reads the fork's transcript back after a Host restart. The native panel search sends to the packaged Host; the shipped profile intentionally returns its `openAt: never` disabled-search error, after which Refresh reads the list. Fixture UI coverage selects a returned search match.

## Tools & terminal
- ✓ Terminal RPC (`environment`, `shells`, `list`, `create`, `rename`, `close`) — M5 transport
- ✓ Terminal streams (`attach`, `retain`) — shared mux; `TerminalWriter` enforces the raw byte budget and the snapshot's encoded-frame window, queueing until acknowledgements
- ◐ Terminal UI — list/create/select/rename/close, attach, resize, exact text input, bracketed paste when the program enables DECSET `2004`, and mouse input for DECSET `1000`/`1002`/`1003` with SGR `1006` or legacy X10 encoding. The incremental mode reader survives split output frames and bounded-output trimming; click, drag, motion, and wheel input use the same ack-tracked writer, preserve order while acknowledgements are pending, and discard queued input on refusal. The bounded screen model also handles ANSI SGR colors, absolute/relative cursor moves, save/restore, erase, wrapping, alternate screen, scrolling regions, insert/delete line and character, wide/combining characters, and `DSR`/`DA` replies. The deleted AccessKit harness checked paste, click, and ack ordering. `native-journey-probe.sh terminal` still connects a terminal to the packaged Host, creates and attaches a real PTY, and launches a TUI process. An isolated Neovim PTY check also confirmed standard `2004`, `1002`, and `1006` interoperability. This verifies packaged Host input/output through the native renderer, not a physical-window pointer session

## Native protocol and packaged evidence — 2026-10-24

`apps/desktop-tauri/scripts/native-protocol-probe.sh` owns the offline loopback checks documented in `client-core/API.md`. Nine HTTP journeys cover Goal lifecycle/stale revisions, command listing/execution, session management and pagination, terminal lifecycle, settings writes/conflicts, plugin/marketplace results, and multipart document/Office preview. Two additional mux cases cover terminal snapshot/input/ack/output/exit and a question wait's malformed frame/remote failure without interrupting a file watch. The probe passes 116 tests across the library, multipart decoder, and native journey integration test.

The packaged runtime tree and native AppImage are present. L2 passes: Host entry parity/lease, plugin/session/page/settings/fork/goal journey across restart, startup/crash/offline faults, disk-full download, crash during download/extract, Office component and engine resolution, Office-to-PDF conversion, signed Host update flow with a mock shell, Rust PTY and flock providers, image parity, AppImage boot, and the native terminal journey on a headless compositor. `packaged-journey-probe.sh` adds packaged Host side-effect evidence for Marketplace install and the signed update flow with a mock shell; the two GUI journeys that clicked native panels (`panels`, `update-ui`) went with the egui harness. These tests use neither a public feed nor a production signing key. A timed-question wait has no live packaged journey: the shipped preset composes the blocking `ask_user_question`, and mounting the `mode: timed` row requires overriding the preset's `config.plugins` array, which changes the model-visible tool surface (invariant 3) and is therefore a product decision. Until a preset mounts that row, the timed path has package-level tests only. No release was published. A later pass on the physical Hyprland desktop covers L3 for rendering, typing, Vietnamese IME, clipboard, theme packs, rebinding, RSS, and Host-death degradation; physical-window pointer input and independent visual review remain open because the compositor exposes no pointer injection.

`prepare-linux-runtime.ts` now materializes a `node-pty` package that re-exports the Rust provider. The terminal service loads `node-pty` through its own `createRequire`, and that require does not consult the launcher's resolve hooks, so a payload without a resolvable package failed every `terminal/create` with `Cannot find module 'node-pty'` even though the provider itself worked. The native terminal journey above is the regression gate for it.

Marketplace installation consumes the completed `ChangeResult` returned by `installBundle`; `waitForInstall` is reserved for a live request identifier. `client-core` sends all `session/page` bounds supported by the Host; the packaged journey reads current history, while older-page `beforeSeq` requests have loopback coverage only.

Native updater source builds a separately signed `manifest-native.json`, embeds its URL and the component-feed URL in AppRun, verifies framed Host readiness and restart messages, presents download/install confirmation, and schedules the outer AppImage after the old process exits. The signed Host update flow passes with a generated test key and mock shell; the native GUI's two confirmation clicks now complete that same signed swap against a fake executable and verify restart. Production signing/publication and a swap from the published feed remain open.

## Verification surfaces
- Windowless UI: `cargo test --manifest-path apps/desktop-tauri/native-app/Cargo.toml` — 185 tests on one gpui binary, of which 8 open the real `DesktopApp` in gpui's test window and assert rendered geometry and shell state (bar heights, dock widths and thresholds, the Changes toggle, page-versus-conversation surfaces, command palette open/dismiss) against `tests/snapshots/shell-<width>x<height>.txt`. No accessibility tree and no pixel comparison exist in this renderer. The ignored test `packaged_shell_runs_a_prompt_through_an_approved_tool` runs through `native-journey-probe.sh shell` against the packaged Host and a mock model: connect, create a Session, prompt, approve an escalated `bash` call, and read back the tool result and assistant turn. Fixture replies prove UI requests and fixture state only; the ignored packaged case owns the Host-side evidence.
- OS-level GUI probes stay in isolated Weston (`gui-evidence-probe.sh`, `appimage-probe.sh`, native journeys) for IME, tray, drag-and-drop, and window behavior — none of which a windowless harness can prove. Pointing devices cannot be injected into that compositor, so pointer-driven review stays manual.
