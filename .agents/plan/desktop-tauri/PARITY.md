# Parity checklist — native desktop vs web client

A screen is done only when it runs on the native app and its probe passes.
Legend: ✓ transport/API available · ◐ native UI partial · ☐ not started

## Core
- ◐ Session list (`session/list`) — separate `session_list.rs` renderer for projected titles, running/blank markers, relative update age, identity on hover, bounded labels, and arrow-key navigation when no text editor owns keyboard input; navigation bounds and label formatting have unit coverage, but no list-specific native probe yet
- ◐ Session viewer / log (`session/page`) — async page with older-page navigation using Host `beforeSeq` and bounded turn windows; every loaded page merges into the same ordered transcript as live events (deduplicated by `seq`), older pages insert ahead of newer rows, and a page window no longer replaces retained history. The raw seq/type event list was removed, so history and live events have one renderer. Packaged journey reads the current page before and after Host restart; pagination is covered by `egui_kittest` against the fixture Host
- ✓ Tool-call status derivation — M2
- ✓ Chat submit (`session/prompt`) + follow (`session/follow`) — composer with **file attachment** and **Cancel turn**; history and live events render through the transcript projection; a mock-model run proves prompt → approval → tool → question on the packaged runtime. The composer holds a stable `id_salt`, because an auto id moved with the transcript above it and silently discarded every keystroke; `Ctrl+N` creates a Session and focuses the composer
- ✓ Chat cancel (`session/cancel`) — composer exposes Cancel turn while the assistant is working
- ✓ Follow stream (`session/follow`) — shared authenticated mux with reconnect; snapshot records and live events feed one transcript
- ◐ Transcript projection — durable user/assistant messages, provider reasoning, tool calls and results, approvals, jobs, todo lists, deliverables, goals, plan mode, feedback, and the streaming assistant draft; `Transcript::merge` accepts history pages, windowed follow snapshots, and live events in any arrival order, sorts by `seq`, projects each event once, and keeps the newest rows under the row/byte budget. `transcript_view.rs` headless tests include a 1,000-row transcript constrained to the viewport scroll region; `egui_kittest` covers opening an old Session, a snapshot arriving during a page load, switching Sessions, tool events, a 2,100-event history, and pagination through the "Load older events" button
- ✓ Permission approval — `$events` mux + allow-once/reject/delegate; `scripts/approval-probe.sh [allow|reject|delegate]` drives a mock model's escalated bash call through every decision on the packaged runtime: allow runs the command (marker outside the workspace), reject and delegate log the audit outcome and never run it
- ◐ Model selection (`session/modelCatalog`, `session/selectModel`) — composer picker groups providers/models, shows the catalog default, selects the model's default effort, and offers its reasoning efforts; a control initializes the profile default, with packaged Host verification pending
- ◐ Session management (`search`, `create`, `rename`, `fork`) — `packaged-journey-probe.sh` completes a turn against a local mock model, forks the Session, and reads the fork's transcript back after a Host restart; search UI still has no list-level probe

## Tools & terminal
- ✓ Terminal RPC (`environment`, `shells`, `list`, `create`, `rename`, `close`) — M5 transport
- ✓ Terminal streams (`attach`, `retain`) — shared mux; `TerminalWriter` enforces the raw byte budget and the snapshot's encoded-frame window, queueing until acknowledgements
- ◐ Terminal UI — list/create/select/rename/close, attach, resize, exact text input, bracketed paste when the program enables DECSET `2004`, and mouse input for DECSET `1000`/`1002`/`1003` with SGR `1006` or legacy X10 encoding. The incremental mode reader survives split output frames and bounded-output trimming; click, drag, motion, and wheel input use the same ack-tracked writer, preserve order while acknowledgements are pending, and discard queued input on refusal. The bounded screen model also handles ANSI SGR colors, absolute/relative cursor moves, save/restore, erase, wrapping, alternate screen, scrolling regions, insert/delete line and character, wide/combining characters, and `DSR`/`DA` replies. `egui_kittest` drives the actual terminal panel: a simulated TUI enables paste/mouse modes, AccessKit clicks `Send as paste` and the screen, and tests assert exact bytes plus acknowledgement ordering. A separate isolated PTY run with Neovim (`TERM=xterm-256color`, `mouse=a`) confirmed it advertised `2004`, `1002`, and `1006`, accepted the same bracketed-paste frame and wrote the pasted lines, and acted on SGR click coordinates; this is protocol compatibility evidence, not a live Host/App UI session. `native-journey-probe.sh terminal` still proves packaged Host terminal create/attach/write/output, not these UI interactions

## Settings & plugins
- ✓ Settings (`describe`, `update`, `replace`, `mutate`, `openSettingsDocument`) — M6
- ✓ Plugin inventory — M6
- ✓ Skills list — `skills/list` in a native tab: name, description, when-to-use, model-invocability, and skill path for the selected session
- ✓ Schedules (`list`, `catalog`, `history`, `delete`, `update`) — M6; per-Session list with delete in egui
- ✓ Workspace files (`read`, `readBytes`, `stat`, `list`) — unary and multipart bytes transport
- ◐ Settings UI — Host namespace/schema/redacted values and guarded path-mutation drafts remain separate from client-local appearance preferences. Native preferences (schema 2, with version-1 files migrated in place) persist theme, zoom, density, corner radius, theme pack (default, high contrast, Solarized, custom), a custom palette per color scheme with nine role colors, interface and code font families, keyboard shortcuts (settings, marketplace, goals, new session), and default Sessions width; they work while disconnected and have validation, migration, and round-trip tests. The custom palette follows the same role names as the OpenDesign token model (background, surface, text, muted, accent, selection, border, warn, error), is edited with swatches plus hex fields, and repaints both schemes. Fonts resolve through fontconfig to an installed file (collections included, first face), lead their egui chain ahead of the bundled faces, and keep the system fallbacks last, with Noto Sans CJK covering CJK text; the editor lists installed families, flags one that is no longer installed, and previews `Aa 0123 — việt · → { code }`. On the physical desktop the panels repaint in Solarized, high contrast, and a custom palette, a rebound Settings chord opens Settings, and both font roles change as chosen. Native file dialogs run off the interface thread, so a slow portal cannot freeze the window: a picked file attaches to the Session, fills the Document preview path, or exports the previewed text. The model picker states why there is no choice ("No provider configured" with a Settings shortcut, or a timeout after ten seconds) instead of waiting forever. The prototype Explorer/source pane is still missing. The Host settings UI edit path is now driven through AccessKit against the fixture Host: opening the section, replacing the draft JSON, saving (path operation payload with `expectedRevision`), reading the new revision back, and a conflict that keeps the draft while the Host value stays put. A live Host write is still unverified
- ◐ Plugin management view — inventory, per-entry enable/disable for patch-controlled rows, bundle enable/disable, marketplace search and install, and agent presets; `packaged-journey-probe.sh` installs the same fixture through a loopback npm registry (`installBundle` with an explicit registry), proves it activates, and removes it; `egui_kittest` drives marketplace search and install through AccessKit (index, query payload, inspect, install) against the fixture Host, including a refusal that must not report success; a live marketplace install through the native UI is still unverified
- ✓ Workspace, session-control, job, account, remote-access, file-watch, and user-question streams — typed clients over the shared mux; probe verifies workspace/follow, session/control, account/watch, remoteAccess/follow, account/watchExpiry, job/list, and workspaceFiles/changes on a real Host (attachWait still needs a live question; everything else reports a frame)

## App shell
- ✓ Native egui window (no webview) — M7a
- ◐ Native layout — `egui_kittest` asserts rail/sidebar/central geometry with widget identity at 1280×860, 1440×900, and 1920×1080, writes a machine-readable rect report, and snapshots the empty shell at three viewports; the older egui headless panel probe also covers 1024×768 and 1119×1381. The harness drives the shipped `tick`/`render` against an in-process Host fixture and a loopback Remote Stream mux, so New Session → select → compose → Send → live reply → Allow/Reject are asserted without a window. Screenshot baselines guard regressions only; no independent visual review
- ✓ Host sidecar launch + cookie auth — M7b
- ✓ Shared Desktop Host lease — `native-lease-probe.sh` proves a second Host is refused and a new Host takes over after owner death
- ✓ Single-instance lock — M7c
- ✓ System tray + product icon + close-to-tray — M7c/M7d
- ✓ Native file dialogs — M7c
- ◐ Native update — Host owns signed metadata verification and atomic AppImage replacement; native presents download/install confirmation and schedules the outer AppImage after the old process exits. `update-flow-probe.mjs` verifies signed Host feed acceptance, artifact replacement, and restart with a mock shell; native prompt handling has unit tests, but a GUI-driven signed swap/restart remains pending
- ◐ AppImage native — native AppImage (87,607,800 bytes) passes `appimage-probe.sh`, including profile seeding, packaged Host boot, and baked update/component feed URLs. The shipped image was driven on the physical Hyprland desktop: boot, authentication, streams, session creation, typing, Vietnamese IME, clipboard paste, theme packs, and Settings shortcuts all work, and killing the Host leaves a clear disconnected state. OS-level use of Retry against a recovered Host, a full-screen TUI inside the native terminal panel, and the updater prompt remain unverified; the windowless AccessKit tests cover the Retry refusal and terminal input interactions, not the physical window. The release lane has not been run or published

## Open parity gaps
- ✓ Composer — multiline egui text editing with Ctrl+Enter submission, a stable id, and a unit-tested key predicate; on the physical desktop, fcitx5 Bamboo composed `vieejt` into `việt` and `wl-copy` + `Ctrl+V` pasted into the focused composer
- ◐ UI hardening — loading, empty, disconnected, and retry states exist on key screens; killing the Host on the physical desktop produced the disconnected state without a crash and kept the session list, `egui_kittest` clicks the disconnected banner's Retry control, asserts the real Host attach handshake attempt, and asserts a refused attach leaves the app disconnected with no transport; a successful reconnect still needs a live Host (the harness has no WebSocket mux), and independent visual review remains pending
- ◐ Document preview — text page, decoded image preview, and Office preview via the Host converter plus local pdftoppm (first page); `office-component-probe.sh` installs the component on the packaged tree, creates a Session, writes a `docx`, and renders it through `officeToPdf/render` (multipart PDF answer); `egui_kittest` drives the native preview pane end to end: the path field, the `officeToPdf/render` payload, the Host-converted PDF, and the local `pdftoppm` raster (306 × 153 px for the fixture page), plus a non-PDF answer that reports the raster failure instead of showing an image
- ✓ Deliverables view — `deliverables/presented` files collect into a panel whose links open the document preview, including records replayed from `session/page` history when an old Session opens
- ✓ Human interaction — question cards answer `ask_user_question` through the `$events` waterfall (options, multi-select, free text, skip); `userQuestions/answer` transports continued questions; `scripts/approval-probe.sh allow` proves the live round trip. `userQuestions/attachWait` yields no frames because Desktop composes the blocking legacy tool, not the timed one
- ✓ Jobs panel — session job list (`job/list`) with per-job output follow (`job/follow`); the approval probe starts a background job and reads its output through `job/follow` on a real Host
- ◐ Goals, todo, plan — Goal panel creates, edits, pauses, resumes, completes, and clears goals through existing `goals/*` RPCs, and runs `/plan` or `/plan off` through `commands/execute`; recent durable todo, goal, and plan events are shown beside it. `packaged-journey-probe.sh` drives the whole goal lifecycle on the packaged Host and reads a live goal back after a restart, so only an interactive GUI review is missing
- ✓ Remote Event `$events` waterfall transport and approval outcomes; projections/control stream UI pending
- ✓ Multipart binary response decoder and prompt attachment upload (`session/uploadFileBinary`)
- ✓ Native probe (`scripts/native-gui-probe.sh`) launches the packaged runtime under a separate headless Weston compositor, waits for Host readiness, authentication, `$events`, and the stream probe; physical-desktop rendering was measured separately with the shipped AppImage
- ✓ RSS measurement on the shipped AppImage over a real Hyprland session: 241 MiB RSS / 228 MiB PSS just after start, 253/238 after connecting, 260/240 with a Session and Settings open, 261/245 with composer text (older source builds measured 263–266 RSS; one model-picker run 205/182)
- ✓ Release binary on the real desktop with an isolated `DSH_HOME` (2026-10-24, after D76/D77): 92.7 MB peak RSS / 79.6 MB PSS at boot, 93.8 MB after creating a Session, 133.5 MB / 120.5 MB after pasting CJK text and opening Settings. The CJK fallback (19.5 MB `.ttc` plus parse cost, ~40 MB total) is now loaded only when CJK text appears; before D77 it was in every session
- ✓ Terminal UI protocol coverage: the AccessKit harness asserts the terminal widget sends bracketed paste, SGR mouse click, and queued wheel bytes in order after ack; parser/tracker tests cover split mode sequences, independent mode resets, X10 bounds, output trimming, and refusal cleanup. Neovim in an isolated PTY (no user profile or compositor) advertised the modes and accepted paste/click sequences; this does not replace live packaged Host plus native UI verification

## Memory gate
- ✓ RSS < 300 MiB measured on a real machine and real GPU: 241–261 MiB RSS / 228–245 MiB PSS on the shipped AppImage (full session data), and 92.7–133.5 MB RSS on the release binary with an isolated Home after D76/D77 — both gates (< 300, and < 250 without CJK text) hold

## Native protocol and packaged evidence — 2026-10-24

`apps/desktop-tauri/scripts/native-protocol-probe.sh` owns the offline loopback checks documented in `client-core/API.md`. Nine HTTP journeys cover Goal lifecycle/stale revisions, command listing/execution, session management and pagination, terminal lifecycle, settings writes/conflicts, plugin/marketplace results, and multipart document/Office preview. Two additional mux cases cover terminal snapshot/input/ack/output/exit and a question wait's malformed frame/remote failure without interrupting a file watch. The probe passes 112 tests across the library, multipart decoder, and native journey integration test.

The packaged runtime tree and native AppImage are present. L2 passes: Host entry parity/lease, plugin/session/page/settings/fork/goal journey across restart, startup/crash/offline faults, disk-full download, crash during download/extract, Office component and engine resolution, Office-to-PDF conversion, signed Host update flow with a mock shell, Rust PTY and flock providers, image parity, AppImage boot, and the native terminal journey on a headless compositor. A timed-question wait has no live packaged journey: the shipped preset composes the blocking `ask_user_question`, and switching the row to `mode: timed` requires overriding the preset's `config.plugins` array, which changes the model-visible tool surface (invariant 3) and is therefore a product decision, not a probe setting. No production signing key was used and no release was published. A later pass on the physical Hyprland desktop covers L3 for rendering, typing, Vietnamese IME, clipboard, theme packs, rebinding, RSS, and Host-death degradation; the retry control, a full-screen TUI inside the terminal panel, an update confirmation, and an independent visual review remain open because the compositor exposes no pointer injection.

`prepare-linux-runtime.ts` now materializes a `node-pty` package that re-exports the Rust provider. The terminal service loads `node-pty` through its own `createRequire`, and that require does not consult the launcher's resolve hooks, so a payload without a resolvable package failed every `terminal/create` with `Cannot find module 'node-pty'` even though the provider itself worked. The native terminal journey above is the regression gate for it.

Marketplace installation consumes the completed `ChangeResult` returned by `installBundle`; `waitForInstall` is reserved for a live request identifier. `client-core` sends all `session/page` bounds supported by the Host; the packaged journey reads current history, while older-page `beforeSeq` requests have loopback coverage only.

Native updater source builds a separately signed `manifest-native.json`, embeds its URL and the component-feed URL in AppRun, verifies framed Host readiness and restart messages, presents download/install confirmation, and schedules the outer AppImage after the old process exits. The signed Host update flow passes with a generated test key and mock shell; production signing/publication and an update initiated from the native GUI remain open.

## Verification surfaces
- Windowless UI: `cargo test --manifest-path apps/desktop-tauri/native-app/Cargo.toml ui_harness` — 19 tests drive the real panels through AccessKit (New Session, Session select, composer text, Send prompt payload, live assistant event, Allow once, Reject, opening an old Session with tool events and a deliverable, a snapshot arriving during a page load, Session switching, a 2,100-event history, pagination through "Load older events", settings save with fixture read-back and conflict, marketplace search/install and refusal, Retry connection attach refusal, Office→PDF preview and raster failure, terminal bracketed paste, and an SGR mouse click plus queued wheel input released by its ack) plus layout rects and three shell snapshots. The fixture Host applies settings path operations to its document and advances revisions, serves marketplace results/install status and Office-converted PDF bytes, and refuses `GET /connect`; these replies prove UI requests, fixture-side state, and rendered results, not production Host side effects. The fixture also answers `session/list`, `session/create`, `session/prompt`, `session/page`, and `model/catalog`; the loopback mux replays frames so a follow stream opened later still receives its snapshot.
- OS-level GUI probes stay in isolated Weston (`gui-evidence-probe.sh`, `appimage-probe.sh`, native journeys) for IME, tray, drag-and-drop, and window behavior — none of which a windowless harness can prove.
